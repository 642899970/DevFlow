# DevFlow (AgentOrchestra) 开发需求文档 v0.1

## 1. 项目概述
构建一个多 Agent 协作式全栈开发平台，允许用户通过自然语言描述需求，系统自动完成架构设计、前后端代码生成、测试用例生成，最终输出可运行的完整项目。平台必须支持用户自由配置当前主流的 AI 模型 API（OpenAI、Anthropic Claude、Xiaomi MiMo、OpenAI 兼容接口等），并允许为不同 Agent 分配不同的模型。

## 2. 用户故事
- **US1**：作为开发者，我希望输入“帮我创建一个带用户注册登录的博客系统”，系统能自动生成结构完整、包含前后端及测试代码的项目目录，并可以在本地运行。
- **US2**：作为开发者，我希望通过一个 YAML 配置文件指定各个 Agent 所用的模型及 API Key，并能方便地在本地切换模型以对比效果或控制成本。
- **US3**：作为开发者，我希望看到每个 Agent 的实时思考过程和工具调用日志，以便理解系统的决策路径。
- **US4**：作为项目审核者，我希望通过运行 Demo 脚本直观体验多 Agent 协作流程，并看到清晰的 Token 消耗统计。

## 3. 功能性需求

### F1：多模型配置与统一调用
- 平台加载 `config/models.yaml`，支持定义多组模型配置。
- 支持模型类型：OpenAI 标准接口、Anthropic Messages API、MiMo Orbit API、自定义 OpenAI 兼容接口。
- 运行时可通过环境变量覆盖 API Key，保障安全。
- 支持模型健康检查（ping 接口）并给出可用性提示。

### F2：Agent 角色定义
- 用户可通过 `config/agents.yaml` 定义 Agent 列表，配置其使用的模型、系统提示词、可用工具集合、最大执行步数等。
- 内置四个标准 Agent：架构师、前端工程师、后端工程师、测试工程师。
- 支持通过命令行参数临时覆盖配置（如指定某个 Agent 临时使用哪个模型）。

### F3：需求解析与任务规划
- 输入一条自然语言需求，系统调用默认模型（可配置）生成结构化的任务 DAG。
- 输出 DAG 需包含任务 ID、类型、负责 Agent、依赖关系。
- 用户可审查并修改规划结果（CLI 提供确认步骤）。

### F4：多 Agent 协作执行
- 按照 DAG 依赖关系并行执行无依赖任务。
- Agent 之间通过共享文件工作区交换信息（接口定义、Schema 文件等）。
- 支持 Agent 在遇到问题时请求协助（如后端 Agent 发现接口描述不清晰，可通知架构师 Agent 澄清）。
- 提供“恢复执行”功能：若执行中断，可从上次已完成任务处继续。

### F5：工具系统
- 提供基础工具集：
  - `read_file(path)` / `write_file(path, content)` — 读写虚拟工作区文件
  - `execute_command(cmd)` — 在隔离环境执行 shell 命令（如 `npm install`）
  - `search_web(query)` — 可选的联网搜索能力
- 工具描述符合 OpenAI function calling 格式，自动适配不同模型的 tool use 调用。

### F6：输出与归档
- 执行完成后，将完整项目目录导出为本地文件夹。
- 同时生成项目 README、运行说明。
- 保存执行日志和 Token 消耗详情到 `logs/` 目录，便于分析。

### F7：CLI 交互界面
- 命令示例：
  ```bash
  devflow new "一个博客系统" --model-config config/models.yaml --agents config/agents.yaml
  ```
- 提供交互模式，逐步确认规划、选择模型等。
- 支持 Dry-run 模式：仅生成规划，不实际执行。

## 4. 非功能性需求
- **可扩展性**：新增模型只需在 Adapter 层添加子类并注册，无需改动调度核心。
- **安全性**：API Key 仅通过环境变量或加密配置文件读取，代码仓库绝不包含密钥。
- **性能**：单个 Agent 会话可在 30 秒内开始响应，并行执行时总体时间不超过最长单任务时间的 1.2 倍（理论最优）。
- **文档**：提供完整的开发者文档和用户指南，包括如何添加新模型、自定义 Agent。

## 5. 技术选型建议
- **编程语言**：Python（生态丰富，LLM 集成库成熟）
- **Agent 框架**：初期可基于 LangGraph 快速搭建，后续可替换为自研调度器以降低依赖。
- **LLM 客户端**：使用官方 SDK（openai、anthropic）+ 自定义 adapter 统一。
- **异步框架**：asyncio + aiohttp
- **配置解析**：PyYAML + pydantic 数据校验
- **虚拟文件系统**：内存临时文件 + 最终导出到磁盘

## 6. 里程碑规划（MVP）
- **M1（第 1-3 天）：**
  - 模型适配层完成，支持 OpenAI、MiMo、Anthropic 三种接口
  - 配置文件解析与校验
  - 单 Agent 基本对话循环（能执行简单的文件读写工具）
- **M2（第 4-7 天）：**
  - 需求规划模块：能用 LLM 生成任务 DAG
  - 多 Agent 调度引擎：支持基于 DAG 的并行执行，Agent 间能读取共享文件
- **M3（第 8-10 天）：**
  - CLI 交互完善，提供 Dry-run、恢复执行、Token 统计
  - 端到端示例用例：生成一个可运行的博客系统项目
  - 编写 README 与 Demo 脚本

## 7. 配置文件示例
- config/models.yaml
```yaml
models:
  - id: mimo-pro
    provider: openai_compatible
    model_name: mimo-v2.5-pro
    base_url: https://api.mimo.xiaomi.com/v1
    api_key_env: MIMO_API_KEY
    default_params:
      temperature: 0.1
      max_tokens: 8000
  - id: gpt4o
    provider: openai
    model_name: gpt-4o
    api_key_env: OPENAI_API_KEY
  - id: sonnet
    provider: anthropic
    model_name: claude-sonnet-4-20250514
    api_key_env: ANTHROPIC_API_KEY
```
- config/agents.yaml
```yaml
agents:
  architect:
    model: mimo-pro
    system_prompt: "You are a system architect..."
    tools: [search_docs, design_db_schema]
    max_iterations: 10
  frontend:
    model: gpt4o
    system_prompt: "You are a frontend expert..."
    tools: [write_file, read_file]
  backend:
    model: sonnet
    system_prompt: "You are a backend engineer..."
    tools: [write_file, read_file, execute_sql]
  tester:
    model: mimo-pro
    system_prompt: "You are a test engineer..."
    tools: [write_file, run_tests]
```

## 8. 验收标准
- 使用至少两种不同提供商的模型（如 MiMo + OpenAI）协作完成同一个示例项目的生成。
- 生成的示例项目可正常运行，前端可访问，后端 API 可响应。
- 执行日志清晰展示每个 Agent 使用的模型、消耗的 Token 数量。
- 配置文件化，更换模型只需修改 YAML 文件，无需改代码。
